# TwinkleBot 产品问题 / 改进台账（Product Issues & Backlog）

> **记录规则（本文件是唯一台账）**
> - **用途**：记录作者在日常使用 / 测试中发现的**产品问题、体验缺陷、能力缺口、改进建议**。代码级 bug 的修复仍走正常提交 / issue，这里是"产品侧待办"的集中看板。
> - **每条一行**，字段固定为：`ID | 区域 | 严重度 | 状态 | 简述 | 相关代码 / 根因`。
> - **ID**：`PI-XXX`（Product Issue，三位递增，不复用）。
> - **状态**：`NEW`（新记录）/ `PLANNED`（已排期）/ `FIXING`（修复中）/ `FIXED`（已修，标提交号）/ `WONTFIX`（明确不修，写原因）。
> - **严重度**：`P0` 阻断 / `P1` 严重 / `P2` 一般 / `P3` 建议。
> - **追加不覆盖**：任何人（含 Bot）新增问题一律追加到表格末尾；修复时只改对应行状态并在"相关代码/根因"里补提交号。
> - **必带源码定位**：每一条的"相关代码/根因"必须写明具体文件路径（+行号），方便后续定位与修复。
> - 新增问题前先查重，避免重复登记。
