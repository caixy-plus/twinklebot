SECURITY GUARDRAILS

把能力交给 AI，把边界留给自己

所有高风险操作、跨工作区写入与敏感路径访问均有硬性策略拦截，绝不越权执行。

  • 敏感文件硬隔离 .env、.ssh、Keychain、vault.json 等路径在策略层永久拒绝读取与修改。
  • 交互式审批与凭证掩码 危险命令弹出审批卡片并支持「仅一次 / 总是允许」；密码与授权码通过遮罩卡片注入，不进入模型上下文。
  • 无界面服务器纯接口模式 当以 DEPLOY_ENV=cloud 部署在云端服务器时，域名首页仅返回 ok，不暴露 Web 控制台，全靠加密 Token 与客户端对接。

CLOUD DEPLOYMENT · AI & HUMAN READY

云端主控模式部署指南（DEPLOY_ENV=cloud）

云端模式会在服务器以「纯接口无界面模式」运行，首页仅返回 ok。你可以直接把右侧提示词贴给 AI 自动完成部署，或按左侧步骤手动配置。

STEP 1 · 准备环境

拉取代码与安装依赖

准备一台 Ubuntu 22.04 / 24.04 云服务器，安装 Node.js 22.13+、Python 3，以及桌面沙箱组件（xfce4、xvfb、x11vnc、novnc）：

git clone https://github.com/caixy-plus/twinklebot.git
cd twinklebot && npm install
STEP 2 · 写入 .env 配置

启用纯接口云端模式与鉴权 Token

云端模式不要求预先填写模型 Key（可在客户端连上后再配 DeepSeek / OpenAI / Gemini），但必须设置两个强随机 Token：

.env（云端最小可用配置） 
DEPLOY_ENV=cloud
HOST=127.0.0.1
PORT=3230
TWINKLEBOT_CLOUD_TOKEN=请替换为你的强随机访问Token
TWINKLEBOT_EXECUTOR_TOKEN=请替换为你的强随机执行器Token
TWINKLEBOT_EXECUTOR_URL=http://127.0.0.1:7300
TWINKLEBOT_NOVNC_PROXY_TARGET=http://127.0.0.1:6080
STEP 3 · 启动服务与反代

守护桌面执行器 + 主服务 + HTTPS/WSS

启动虚拟桌面（:1, 1440×900）与 noVNC（6080），运行 python3 executor/executor.py（监听 7300）与 npm start（监听 3230）。 对外通过 Nginx / Caddy 配置 HTTPS 反向代理，并放行 WebSocket（/ws 与 /novnc/websockify）。

STEP 4 · 客户端连接

在桌面端或手机端接入云端节点

直接用浏览器打开域名只会看到 ok（安全隔离）。请打开 TwinkleBot 桌面端或 Android App → 点击「切换账号 → 添加云端节点」→ 填入你的服务器域名（如 https://bot.example.com）与 TWINKLEBOT_CLOUD_TOKEN 即可开始使用。

推荐 · 一键交给 AI 部署

把下面整段提示词贴给你的 AI 助手

支持 Cursor、Claude Code、Codex、OpenClaw 或任意具备终端/SSH 权限的 AI Agent。

请帮我在这台 Linux（Ubuntu）云服务器上部署 TwinkleBot 的云端主控模式（DEPLOY_ENV=cloud），要求全程自动化完成并做连通性自检：

1. 环境检查与安装：
   - 确认 Node.js >= 22.13 和 Python 3 已安装（若不足请升级）。
   - 拉取仓库：git clone https://github.com/caixy-plus/twinklebot.git（若目录已存在则 git pull），执行 npm install。
   - 安装并启动虚拟桌面沙箱与远程看屏服务（Xvfb + XFCE :1 1440x900、x11vnc、websockify/noVNC 监听 127.0.0.1:6080）。

2. 生成强随机密钥并写入 .env：
   - 生成两个独立的 32 字节随机十六进制 Token：TWINKLEBOT_CLOUD_TOKEN 和 TWINKLEBOT_EXECUTOR_TOKEN。
   - 在项目根目录写入 .env：
     DEPLOY_ENV=cloud
     HOST=127.0.0.1
     PORT=3230
     TWINKLEBOT_CLOUD_TOKEN=<随机Token1>
     TWINKLEBOT_EXECUTOR_TOKEN=<随机Token2>
     TWINKLEBOT_EXECUTOR_URL=http://127.0.0.1:7300
     TWINKLEBOT_NOVNC_PROXY_TARGET=http://127.0.0.1:6080

3. 配置系统守护进程（systemd）：
   - 创建并启动 twinklebot-executor.service：加载 .env 中的 TWINKLEBOT_EXECUTOR_TOKEN，在 DISPLAY=:1 下运行 python3 executor/executor.py（监听 127.0.0.1:7300）。
   - 创建并启动 twinklebot-server.service：加载 .env 并运行 node server.js（监听 127.0.0.1:3230）。

4. 配置反向代理与 HTTPS：
   - 若服务器已绑定域名，用 Caddy 或 Nginx 反代到 127.0.0.1:3230，务必正确透传 WebSocket Upgrade 头（支持 /ws 与 /novnc/websockify）。
   - 若暂无域名，请提示我服务器公网 IP:3230 的安全组放行方式（此时需将 HOST 设为 0.0.0.0）。

5. 部署后自检并把连接信息输出给我：
   - 验证 curl -s http://127.0.0.1:3230/ 返回 ok。
   - 验证带上 Authorization: Bearer <TWINKLEBOT_CLOUD_TOKEN> 请求 /api/system/diagnostics 返回 200 且 executorOnline 为 true。
   - 最后清晰输出：客户端接入地址、TWINKLEBOT_CLOUD_TOKEN，并提醒我在 TwinkleBot 桌面端或 Android App 的「切换账号 → 添加云端节点」中填入以上两项，连接后再在设置里配置 DeepSeek / OpenAI / Gemini 等模型供应商。
