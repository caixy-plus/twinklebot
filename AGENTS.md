# TwinkleBot

Multi-Bot AI desktop & mobile agent: orchestrates Gemini / OpenAI / DeepSeek / Anthropic / Vertex AI models with a local or cloud runtime, OrbStack / WSL2 / cloud Ubuntu XFCE sandbox (`:1`, 1440x900), and cross-platform Host Executor bridge.

- **Stack & Build**: Node.js 22.13+, ESM, TypeScript (`tsc`). `npm run build:ts` runs `tsconfig.shared.json` (`src/shared/`), `npm run build:web` (`build:css` + React 19 Vite SPA -> `public/dist/` + SSR -> `dist-server/web-ssr/` + `scripts/build-web.mjs --public-meta`, typechecked via `tsconfig.web.json`), `tsconfig.json` (`dist-server/`), `scripts/copy-prompts.mjs`, `scripts/build-core-bundle.mjs` (`dist-server/core-runtime/server-bundle.mjs`), and `tsconfig.landing.json` (`landing/dist/`). Pure-JS runtime dependencies only: `@google/genai` (>= 2.29.1; use the Interactions API only for Gemini, never `generateContent` or legacy `@google/generative-ai`), `@larksuiteoapi/node-sdk` (Feishu / Lark official SDK), and `grammy` (Telegram Bot SDK) — all bundled into `dist-server/core-runtime/server-bundle.mjs` so they ship via `ota-only`.
- **Architecture**:
  - `src/shared/` holds shared entity types, DTOs, and browser-safe modules (`accounts-store.ts`, `skills-catalog.ts`, `context-compression.ts`, `versioning.ts`).
  - `src/server/` serves `127.0.0.1:3230` (via `dist-server/src/server/index.js`, split into `context.ts`, `http-utils.ts`, `static.ts`, and `routes/*.ts`).
  - `src/agent/` holds the agent loop, smart router, context compression, policy (`policy.ts`), model adapters (`providers/*.ts`), bot tools (`bot-tools/*.ts`), `prompts/`, and `knowledge/` (runtime self-knowledge via `app_knowledge`).
  - `src/lib/` owns LAN discovery, pairing auth, remote relay (`127.0.0.1:3231`), Feishu/Telegram channels, mail, MCP (`mcp-client.ts`), web search, billing, and host bridge.
  - `src/store/` owns JSON/NDJSON session, event, history, skill, schedule, and vault persistence under `data/`.
  - `src/web/` (`main.tsx`, `ssr-entry.tsx`, `components/`, `hooks/`, `services/`, `state/`, `styles/`) + `public/` form the React 19 + Vite SPA for Web/Desktop/Mobile UI; `APP_TARGET=mobile node scripts/build-web.mjs` strips backend/Electron files into `dist-web/` for Capacitor (`android/` with native `LanDiscoveryPlugin`, `ios/`).
  - `src/electron/` + `electron/preload.cjs` form a thin Electron shell spawning `dist-server/core-runtime/server-bundle.mjs` (`backend-supervisor.ts` + `core-ota.ts`); standalone CLI blocks inside worker-bundled modules (e.g. `src/server/index.ts`) must guard `TWINKLEBOT_DESKTOP_WORKER !== "1"`. `executor/executor.py` runs inside Ubuntu (Python 3 stdlib only, `twinklebot-executor.service`, port `7300`, bearer token).
- **Commands**: `npm run typecheck`, `npm run build:ts`, `npm run build:ota`, `npm test` (builds TS then runs `node --test`), `npm run electron:pack:mac` / `electron:dist`, `npm run mobile:build:web` / `mobile:apk:debug`, and `orb -m ubuntu python3 -m unittest discover -s executor -v`. For automated UI/E2E testing, prefer `http://127.0.0.1:3230` directly.
- **Permission Gate & Anti-Over-Prompting Invariants** (3-Zone Policy Model):
  - **Bot's Computer (`sandboxMode === "full"`)**: Free-roam inside the isolated Ubuntu sandbox. ALL `SANDBOX_TOOLS` (including interactive GUI/browser tools: `click`, `type_text`, `key`, `browser_click`, `browser_type`, `write_file`, `edit_file`, `run_shell`) MUST auto-allow even if the LLM passes spurious `risk: "high"`, and MUST NOT be checked against host `writeRoots`. **Never** re-introduce a `SANDBOX_EXTERNAL_INTERACTION_TOOLS` carve-out or let `autoAudit` intercept sandbox clicks/typing in `full` mode. Only hardcoded non-bypassable guardrails (`.ssh`/`.env`/keychain/`vault.json`/`accounts.json`/self-control MCP deny + cross-Bot private workspace confirmation) and explicit user `askRules`/`denyRules` apply.
  - **Your Computer (`hostExecutionMode === "always"`)**: High-autonomy Always Allow mode. Auto-allow routine host commands/writes/edits, safe scratch & own-workspace `rm` (`/tmp`, `/var/tmp`, `os.tmpdir()`, own `botWorkspaceRoot` via `isSafeScratchRmCommand`), read-only host/MCP tools (`isReadOnlyHostOrMcpTool`), and routine KimiCU actions; deterministically confirm truly destructive host commands (`sudo`, non-scratch/home/system `rm`, `git push --force`, sensitive configs) and hardcoded guardrails. Explicit wildcard `allowRules` must apply in `always`/`full` modes.
  - **Live Settings & Clean Defaults**: Re-read live `store.readSettings()` before each `assessToolCall` inside batched tool loops (`src/agent/loop.ts`), never pre-seed `"sudo"` or hidden rules in `DEFAULT_POLICY.askRules` (`src/server/http-utils.ts`), deduplicate persisted `allowRules`/`askRules` by `(tool, pattern)` (`src/server/routes/sessions.ts`), and keep `DRAFT_REUSE_ELIGIBLE_TOOLS` covering `type_text` and `mcp__kimi_cu__*`.
  - **Prompt & Tool Schema Anti-Over-Prompting (`src/agent/tools.ts`, `src/agent/host-tools.ts`, `src/lib/mcp-client.ts`, `src/agent/prompts/*.md`)**: Keep tool `risk` as an **optional 3-level enum `["low", "medium", "high"]`** (never revert to binary `["low", "high"]` or `"Always use 'low'..."` phrasing), and omit `risk` on sandbox-internal and read-only MCP tools. **Never** add sweeping `ALWAYS` / `"or submitting forms"` / bottom-of-prompt recency-bias warnings to `safety-and-style.md`, `dual-computer.md`, or MCP tool descriptions that coerce LLMs into flagging routine clicks/typing as `risk: "high"`. Document sandbox interactive GUI/browser tools as auto-allowed in `dual-computer.md`, and keep Settings `autoAudit` labeled `高风险操作智能确认` / Smart High-Risk Confirmation.
- **KimiCU MCP Self-Discovery & Platform Gating**:
  - Never hardcode a fixed KimiCU tool count or static schema in prompts, policy, or UI (`src/lib/mcp-client.ts`, `src/agent/prompt.ts`, `src/web/components/modals/SettingsModal.tsx`); rely on live MCP `tools/list`, binary `(mtimeMs, size)` auto-reload, `notifications/tools/list_changed`, `inferMcpToolReadOnly`, and `buildKimiCuPromptSection` so KimiCU upgrades adapt automatically without an OTA.
  - Gate OS-specific skills (e.g., macOS-only `kimi-cu`) on unsupported platforms while preserving button label (`添加`) and hover tooltip copy.
- **Versioning & GitHub Releases (`v1.0.0` Baseline, `v1.0.4+` Core OTA Shell Baseline, default repo `caixy-plus/twinklebot`)**:
  - **Default Hot-Update Rule (No Shell Version Bump on `ota-only`)**: Because shell versions are strictly bound to OTA (`v1.0.5+` forces full shell reinstall whenever a newer `X.Y.Z` exists), whenever changes can ship via hot update (`src/server/**`, `src/agent/**` including `prompts/*.md`, `src/store/**`, `src/lib/**`, `src/shared/**`, `src/web/**`, `public/**`, `executor/executor.py`, or bundled pure-JS deps like `@google/genai`) and do **not** touch native shell layers (`src/electron/**`, `electron/preload.cjs`, `electron/*`, `electron-builder` config, `android/**`, `ios/**`, `capacitor.config.*`, or Electron/Capacitor native deps), **do NOT run `npm run version:bump` and keep `X.Y.Z` & native `buildCode` unchanged** — release via `ota-*` / `mode=ota-only`, which advances only `coreBuild` / `webBuild` (`YYYYMMDD.HHmmss-<hash>`), builds `twinklebot-core-desktop.tar.gz` + `twinklebot-web-mobile.tar.gz`, and inherits existing native installer links from `ota-channel`.
  - **Version Bump Convention** (aligned with `cc-gateway`, `MAJOR.MINOR.PATCH` — **only** when native shell layers change or user explicitly asks for full installers):
    - `PATCH` ranges **0–9**: when it reaches `9`, the next bump rolls over to `0` and increments `MINOR` (e.g. `1.0.9 → 1.1.0`, `1.5.9 → 1.6.0`).
    - `MINOR` ranges **0–19**: when it reaches `19`, the next bump rolls over to `0` and increments `MAJOR` (e.g. `1.19.9 → 2.0.0`).
    - Mobile native `buildCode` (Android `versionCode` / iOS `CURRENT_PROJECT_VERSION`) increments `+1` monotonically on each native shell version bump.
    - Use `npm run version:bump` (`--patch` / `--minor` / `--major` / `--set=X.Y.Z` / `--dry-run`) to atomically synchronize `version-policy.json`, `package.json`, `package-lock.json`, `android/app/build.gradle`, and `ios/App/App.xcodeproj/project.pbxproj` (and raise `shells.desktop.minVersionForCoreOta` whenever new Electron shell/IPC capabilities are required).
  - `version-policy.json` is the single source of truth for decoupled `shells.{desktop, android, ios}` versions vs `minVersionForOta` / `minVersionForCoreOta` / `minBuildCodeForOta` and `backend` `apiCapabilities` (enforced by unit tests against `package.json`, `android/app/build.gradle`, and `ios/App/App.xcodeproj/project.pbxproj`, including `PATCH 0–9` / `MINOR 0–19` bounds).
  - Before pushing a full release tag `vX.Y.Z`, ensure `package.json` and `version-policy.json` match `X.Y.Z` exactly (enforced by `.github/workflows/release.yml`). Never bump versions or push release tags autonomously unless the user explicitly asks; keep published GitHub Release notes bilingual (`中文 / English`).
  - Pushing to `main` runs `.github/workflows/ci.yml` only (build & packaging check only — never runs tests in CI, never auto-publishes client updates, and ignores `README*.md`, `AGENTS.md`, `CLAUDE.md`, `LICENSE`, `docs/**`, `.agents/**`). Bilingual docs use `README.md` (English primary) + `README.zh-CN.md` (Simplified Chinese). Push tag `ota-*` (or dispatch `release.yml` with `mode=ota-only`) for Core + Web OTA hot updates without changing shell versions; push tag `v*` (or `mode=full`) for full multi-platform installers + OTA.
  - **Always monitor GitHub CI & Release packaging to green before finishing**: Whenever pushing to GitHub or triggering `.github/workflows/ci.yml` / `.github/workflows/release.yml` (including shell packaging and OTA releases), do **NOT** conclude right after pushing — monitor the run via `gh run watch <id> --exit-status` until every required job finishes `success`, verify the published GitHub Release (`isDraft: false`, expected assets, and `ota-channel` manifest for releases), and diagnose/fix/re-run if any job fails or is unexpectedly skipped.
  - Because Mobile/Web clients may switch dynamically between LAN and Cloud backend nodes running different versions, gate any post-`1.0.0` backend-dependent UI feature via `hasConnectedNodeCapability("<cap>")` (`src/web/services/ota-updater.ts`) and register new backend capabilities in `CURRENT_API_CAPABILITIES` (`src/shared/versioning.ts`) + `version-policy.json` (`ota-only` refreshes `backend.apiCapabilities` too) while keeping `v1.0.0` baseline features backward-compatible.
  - **Strict Shell-vs-OTA Binding & Android Release Signing**: Whenever raising native shell version/capabilities, also bump `minVersionForOta` / `minVersionForCoreOta` / `minBuildCodeForOta` in `version-policy.json` so older shells require installer upgrades instead of stale OTA; Android full releases sign `TwinkleBot-mobile-release.apk` (portrait-locked `PortraitCaptureActivity`, 4KB `zipalign -p -f 4` + `apksigner verify`, never publish `-unsigned.apk`); stop once GitHub packaging + official non-draft release + `ota-channel` verify green (no unrequested post-build security testing).
  - **Unified Client Account Model & Clean Fresh-Install Defaults**: UI uses strictly `本地账号 / Local Account` (desktop self, or mobile LAN + 6-digit pairing code) and `云端账号 / Cloud Account` (manual URL / camera QR, internal `nodeDeployEnv` hidden, desktop self-connect blocked, Bot `account_manage` never auto-switches); keep fresh installs free of pre-seeded sample memories, schedules, or vault entries, and keep Cron as the single backing schedule format.
  - **Electron Worker `AbortSignal` Gotcha**: `ELECTRON_RUN_AS_NODE=1` (`fetch` / `new Request`) rejects polyfilled `AbortSignal` objects (`grammy` `abort-controller`) unless normalized to `globalThis.AbortSignal` (`wrapFetchWithNativeAbortSignal` in `src/lib/channel-integrations.ts`).
- **Tiered E2E Skill (`/twinklebot-e2e`) & Feature-Sync / Release Gate Convention**:
  - Canonical reusable Agent Skill lives at `.agents/skills/twinklebot-e2e/SKILL.md` (symlinked into `.claude/skills` and `.pi/skills`, with slash entry points for OpenCode `.opencode/commands/twinklebot-e2e.md` and Pi `.pi/prompts/twinklebot-e2e.md`), backed by machine-readable `references/catalog.json` and `references/test-plan.md`.
  - **Headless by default**: Automated E2E runs Chrome in headless mode (`--headless=new`, `slowMoMs = 0`) by default across all platforms (including local macOS) — do not launch visible browser windows unless the user explicitly asks for visual debugging (`TWINKLEBOT_E2E_HEADED=1`).
  - **No trigger on small local preview edits**: Do **NOT** auto-trigger E2E test runs or interrupt the user when making small local tweaks, UI adjustments, or quick local previews. Only run E2E locally when the user explicitly asks (`/twinklebot-e2e ...`) or at the GitHub Release build boundary.
  - **GitHub Release / version build interactive E2E gate**: Whenever preparing a GitHub version build (running `version:bump` for release, pushing `v*` / `ota-*` tags, or dispatching `.github/workflows/release.yml`), automatically inspect impacted areas via `npm run e2e:sync-check -- --since-last-tag` and **actively ask the user** whether to run automated E2E tests **locally** and at which level (`affected+p0` **recommended default** = changed areas + P0 core; `all` = full 14-suite / 110-case suite; `p0+p1`; `p0`; `affected`; or `skip`). `release.yml` is build-only by default (`e2e_level=skip`, with optional CI opt-in), and both `scripts/run-e2e.mjs` (`--tier=`, `--suite=`, `--case=`, `--list`, `--audit`, `--clean`) and `release.yml` (`e2e_level` input) support all 6 levels.
  - **Catalog sync & 6-dimension audit on new features**: When adding brand-new user-facing features (new routes under `src/server/routes/`, new UI components under `src/web/components/`, new bot tools under `src/agent/bot-tools/`, or new `executor/executor.py` endpoints), keep `references/catalog.json`, `references/test-plan.md`, and `test/e2e/*.e2e.ts` in sync and pass `npm run e2e:audit` (100% across source files, HTTP routes, tools, executor endpoints, web components, and API capabilities) before committing (enable local non-blocking hooks via `npm run hooks:install`).
  - **Report locations**: Raw JSON/screenshots stay gitignored under `test-results/`; human-readable Markdown reports auto-generate to `test-results/reports/latest.md` (and timestamped `e2e-report-*.md`). Archive milestone reports to `docs/e2e-reports/` via `npm run e2e:report:archive`.
- **Product Issues Backlog (`docs/product-issues.md`)**: `docs/product-issues.md` is the single product issues / improvement backlog (`PI-XXX`, append-only, problem + exact `file:line` root cause only — never write fix proposals into it). Whenever fixing a tracked `PI-XXX` item, update its status column in `docs/product-issues.md` to `FIXED (<short-sha>)`.
- **Product Terminology (UI Copy)**: Always refer to both local/LAN and cloud backends as **「账号」** (`本地账号` / `云端账号` / `切换账号`) in user-facing UI copy, banners, and docs — never expose internal engineering jargon such as "节点" (`lanNode*` / `nodeOpen`) to users.
- **Security**: Never commit or log `.env`, API keys, the executor token, or `data/`.
