# 多账号、外网中继与版本更新机制

## 统一账号模型与产品术语规范

- **面向用户统一称「账号」**：界面、提示文案与 Bot 回复中**一律使用「本地账号」「云端账号」「切换账号」**，绝不使用“节点”“服务器节点”等内部工程词。
- **桌面端 vs 移动端账号能力差异**：
  - **桌面端**：本机运行时默认持有 1 个不可删除的 **「本地账号」**；额外可添加多台远程/中继/云服务器作为 **「云端账号」**，并严格拦截本机自连（不允许把桌面本机 loopback 或自己的外网中继地址再添回给自己）。
  - **移动端**：没有手机本地沙盒后端，只包含局域网 **「本地账号」**（局域网发现/手动 IP + 6 位配对码）与跨网 **「云端账号」**（相机扫码或手动填写公网地址与令牌）；未连上任何可用账号时保持断连门禁页保护。
- **禁止 Bot 代切当前工作区**：管理员 Bot 可调用 `account_manage` 列出脱敏账号、测试连通性、配置或移除（限 App 内）远端账号，但**绝不会也不应自动切换用户当前所在工作区**——必须明确告知用户在桌面左下角账号菜单或手机账号面板中手动点击切换。

## 外网中继（远程访问自己电脑上的 TwinkleBot）

- **配置入口**：桌面端 **「设置 → 外网中继」**（位于左侧菜单「通用」正下方；只有当前连在本机桌面账号时显示）。
- **核心架构**：开启后本机内置的 **专口强鉴权中继监听（默认 `3231` 端口）** 启动，所有 HTTP / WebSocket / noVNC 请求强制校验 Bearer Token 或 `?token=` 一次性换取的 HttpOnly Cookie，且在公网中继口上**禁止修改中继自身配置**（防止越权锁死）；桌面主监听 `127.0.0.1:3230` 本身不暴露给公网。
- **常见配置流程**：
  1. 选择运行模式：**内置托管 `frpc`（推荐）**（填入公网域名/IP、端口、WSS TLS 路径与握手令牌等，支持防 Mac 空闲休眠 `caffeinate`）或 **外部自建反代**（仅开本机强鉴权中继端口供自有 Caddy / Nginx / Cloudflare Tunnel 转发）。
  2. 点击 **「保存并应用」** 后，再点 **「检测公网连通性」**（会同时验证带令牌返 200 且不带令牌被 401/403 拦截）。
  3. 用手机端 TwinkleBot **「云端账号 → 扫码添加」** 扫描界面生成的二维码，或复制 `twinklebot://...` 配对链接完成免手输接入。
  4. 若用户已有自备 VPS，可展开页面下方的 **「VPS 服务端配置生成」** 一键导出配套 `frps.toml` 与 `Caddyfile` 片段。

## 版本治理与自我更新（`self_update` / OTA）

- **严格壳-OTA 版本绑定**：自 `v1.0.5+` 起，热更新严格绑定原生壳最低版本（例如修改了 Electron 主进程或 Android/iOS 原生代码的版本会抬升 `minVersionForOta` / `minBuildCodeForOta`）。如果 GitHub Releases 上存在更新的原生壳，`check` 会返回 `shell-update-required`，必须下载新版安装包覆盖安装，不能跳过壳版本直接 OTA。
- **OTA 热更新涵盖范围**：
  - **桌面端 Core OTA**：在线更新 Node 后端 `server-bundle.mjs`、前端静态页面、`executor.py` 与内置系统提示词/自知文档库；**不会更新用户自己的外部 AI 大模型权重或 API**。
  - **移动端 Web OTA**：在线更新 Capacitor `dist-web/` 前端静态资源包，由手机端「关于 TwinkleBot」页面检查并触发。
- **Bot 自我更新能力（`self_update`）**：
  - 任意 Bot 都可调用 `self_update(action: "status" | "check")` 查看当前 Core Build / Web Build 与 GitHub Release 兼容性；
  - 只有 **管理员 Bot** 可执行 `apply`（强制核对 `minVersionForCoreOta` 与 SHA-256，若当前有正在进行的对话会**安全排队，等本轮 Bot 回复结束后自动平滑重启切换新内核**，并带 Watchdog 健康检查失败自动回滚）或 `rollback`（`previous` 上一稳定版 / `builtin` 随包内置基线）。
